# Plan: RPA Outreach Tool for Canon Hackathon Recruitment

**Status:** Draft
**Created:** 2026-03-25

## Requirements

- Browser automation tool that scrapes DoraHacks hackathon participant profiles and sends personalized DM invitations via DoraHacks messaging
- Three-stage pipeline: Scrape -> Filter -> Send (all through DoraHacks platform)
- Scrape 2,500-5,000 profiles to target 500 registrations (~10-20% conversion)
- SQLite storage with dedup, status tracking, and queryable schema
- Relevance scoring by keywords (crypto, AI/ML, sports, generic)
- DM sending through DoraHacks messaging with personalized templates (4 variants), randomized delays, rate caps, dry-run mode, and stop-on-error
- DOM recon step built into the pipeline — agent discovers selectors from saved HTML snapshots, no manual prereqs
- Lives in `rpa-outreach/` directory within claude-code-config repo (may move to own repo later)
- Tech: Playwright (TypeScript), better-sqlite3, Node.js
- Configurable selectors (not hardcoded) so page structure changes don't require code changes

## Approach

Standalone Node.js CLI tool with four subcommands (`scrape`, `filter`, `send`, `status`). Playwright handles all browser automation in headed mode (DoraHacks is an SPA). SQLite is the single data store — every stage reads/writes the `prospects` table.

**DOM recon (built into pipeline):** Before writing scraper or sender logic, a dedicated recon step uses Playwright to navigate DoraHacks pages, save full-page HTML snapshots + screenshots to a `recon/` directory, then the agent analyzes the saved HTML to identify CSS selectors and writes `config/selectors.json`. This eliminates any manual DOM inspection prereq. The recon script is also kept in the repo so selectors can be re-discovered when DoraHacks changes their DOM.

**Authentication:** Playwright runs in headed mode for initial login. User logs into DoraHacks manually once; the script persists the browser context (cookies/storage) to a local `auth/` directory and reuses it for subsequent runs. No credentials stored in code.

**Selector resilience:** All CSS/XPath selectors live in `config/selectors.json`, not in source code. When DoraHacks changes their DOM, re-run the recon script and update the config — no code changes needed.

**Safety-first DM sending:** Dry-run mode is the default. Live sending requires an explicit `--live` flag. Rate limiting, batch caps, and captcha/block detection are always active. DMs are sent through DoraHacks's built-in messaging system.

## Risks and open questions

1. **[Resolved] Repo location** — `rpa-outreach/` directory in claude-code-config. May move to own repo later once validated.
2. **[P2] DoraHacks anti-bot measures** — May encounter captchas or rate limiting during scraping or DM sending. Mitigation: respectful delays between page loads, headed mode (not headless), session persistence, stop-on-error detection.
3. **[P2] Message copy** — Brief says templates need to be written by Carlos/marketing. Ship with placeholder templates; swap for final copy before going live.
4. **[P2] Target hackathon URLs** — Need specific DoraHacks hackathon pages to scrape. Can start with any recent ones for development; final list curated before production run.
5. **[P2] DoraHacks DM availability** — Not all profiles may have DM enabled. Sender must handle cases where the DM option is unavailable and skip gracefully.

## Decision log

| Decision | Alternatives considered | Rationale |
|----------|------------------------|-----------|
| Directory in claude-code-config | Own repo, monorepo subdirectory | Start co-located for fast iteration; move to own repo once validated. Avoids repo creation overhead during POC. |
| Playwright over Puppeteer | Puppeteer, Selenium | Better SPA support, built-in waiting, headed + headless modes, context persistence for auth |
| SQLite over JSON files | JSON flat files, PostgreSQL | Queryable, supports dedup/filtering natively, no server needed, brief recommends it |
| Selectors in config file | Hardcoded in source | DoraHacks DOM will change — config-only updates are faster than code changes |
| DOM recon as pipeline step | Manual inspection prereq, hardcoded selectors | Agent discovers selectors autonomously from saved HTML. Recon script stays in repo for re-running when DOM changes. |
| Dry-run as default | Live as default | Safety-first: review what would be sent before sending. Explicit --live flag required. |
| Headed mode for auth | Headless + cookie injection, env var credentials | Simplest and most reliable — user logs in once via real browser, session persisted automatically |
| commander for CLI | yargs, raw process.argv | Lightweight, well-typed, standard for Node CLI tools |
| DMs via DoraHacks messaging | Email, Twitter DMs, Discord | DoraHacks is where the target users are active. Platform-native messaging has highest open rates. |
