# rpa-outreach

Browser automation tool for DoraHacks hackathon recruitment outreach. Scrapes participant profiles, scores them by relevance, and sends personalized DMs through DoraHacks messaging.

## Prerequisites

- Node.js >= 22
- Playwright browsers installed

## Setup

```bash
cd rpa-outreach
npm install
npx playwright install chromium
npm run build
```

## Pipeline overview

The tool runs a three-stage pipeline: **Scrape** -> **Filter** -> **Send**.

1. **Recon** — Discover CSS selectors from live DoraHacks pages (run once, re-run when DOM changes)
2. **Scrape** — Extract participant profiles from hackathon pages into SQLite
3. **Filter** — Score prospects by relevance (0-10) and tag by interest category
4. **Send** — DM filtered prospects via DoraHacks messaging (dry-run by default)

## Authentication

The tool uses Playwright in headed mode. On first run of any browser command (`recon`, `scrape`, `send`), a browser window opens for you to log into DoraHacks manually. The session is saved to `auth/` and reused for subsequent runs.

The `auth/` directory is gitignored. No credentials are stored in code.

## Usage

### recon — Discover selectors

Navigates DoraHacks pages, saves HTML snapshots and screenshots to `recon/`, and writes discovered CSS selectors to `config/selectors.json`.

```bash
# Full recon (scraper + DM pages)
npx rpa-outreach recon

# Scraper pages only
npx rpa-outreach recon --scraper-only

# DM pages only
npx rpa-outreach recon --dm-only
```

### scrape — Extract profiles

Scrapes participant profiles from all hackathons listed in `config/hackathons.json`. Handles pagination/infinite scroll, deduplicates by username, and stores results in SQLite.

```bash
npx rpa-outreach scrape

# Use a custom database path
npx rpa-outreach scrape --db my-outreach.db
```

### filter — Score and tag prospects

Scores each scraped prospect 0-10 based on keyword matching in their bio and tags. Assigns an interest category (crypto, ai-ml, sports, or generic) and updates status to `filtered`.

```bash
npx rpa-outreach filter

npx rpa-outreach filter --db my-outreach.db
```

### send — DM prospects

Sends personalized messages to filtered prospects through DoraHacks messaging. **Dry-run is the default** — no messages are sent unless you pass `--live`.

```bash
# Dry-run (preview messages, no sending)
npx rpa-outreach send \
  --listing-url "https://dorahacks.io/hackathon/canon" \
  --hackathon-name "Canon Prediction Market Hackathon"

# Live mode (actually sends DMs)
npx rpa-outreach send \
  --listing-url "https://dorahacks.io/hackathon/canon" \
  --hackathon-name "Canon Prediction Market Hackathon" \
  --live

# Override rate limits
npx rpa-outreach send \
  --listing-url "https://dorahacks.io/hackathon/canon" \
  --hackathon-name "Canon Prediction Market Hackathon" \
  --live \
  --batch-limit 50 \
  --rate-cap 15
```

| Flag | Description | Default |
|------|-------------|---------|
| `--listing-url <url>` | Canon listing URL included in messages | **required** |
| `--hackathon-name <name>` | Hackathon name for personalization | **required** |
| `--live` | Send messages for real | `false` (dry-run) |
| `--dry-run` | Preview without sending | `true` |
| `--db <path>` | SQLite database path | `outreach.db` |
| `--batch-limit <n>` | Max messages per session | from `config/defaults.json` |
| `--rate-cap <n>` | Max messages per hour | from `config/defaults.json` |

Safety controls active in live mode:
- Randomized delays between messages (30-90s default)
- Rate cap (25/hour default)
- Batch limit (125/session default)
- Stop-on-error: pauses on captcha, block, or rate limit detection

### status — Pipeline report

Shows aggregate counts by pipeline stage.

```bash
npx rpa-outreach status

npx rpa-outreach status --db my-outreach.db
```

## Config files

All configuration lives in `config/`. No code changes needed to adjust behavior.

### config/selectors.json

CSS selectors for DoraHacks page elements. Generated by the `recon` command. Two sections:

| Section | Keys | Purpose |
|---------|------|---------|
| `scraper` | `profile_list_container`, `profile_card`, `username`, `profile_url`, `bio`, `tags` | Selectors for hackathon participant pages |
| `dm` | `dm_button`, `message_input`, `send_button`, `confirmation_indicator` | Selectors for the DM/messaging interface |

### config/hackathons.json

Array of hackathon URLs to scrape:

```json
[
  {
    "url": "https://dorahacks.io/hackathon/example/buidl",
    "name": "Example Hackathon"
  }
]
```

Add entries here before running `scrape`. Each entry needs a `url` (the hackathon's BUIDLer/participant page) and a `name` (used for tracking which hackathon a profile came from).

### config/defaults.json

Rate limiting and delay configuration:

| Key | Description | Default |
|-----|-------------|---------|
| `delay_min_ms` | Minimum delay between DMs (ms) | `30000` |
| `delay_max_ms` | Maximum delay between DMs (ms) | `90000` |
| `rate_cap_per_hour` | Max DMs per hour | `25` |
| `batch_limit_per_session` | Max DMs per session | `125` |
| `scrape_delay_ms` | Delay between page loads when scraping (ms) | `2000` |

### templates/

Four message template variants, auto-selected by the prospect's interest tag:

| File | Interest category | When used |
|------|-------------------|-----------|
| `generic.txt` | generic / unknown | Fallback for untagged prospects |
| `crypto.txt` | crypto | Bio/tags mention blockchain, web3, DeFi, etc. |
| `ai-ml.txt` | ai-ml | Bio/tags mention AI, ML, machine learning, etc. |
| `sports.txt` | sports | Bio/tags mention sports, betting, etc. |

Templates support these tokens:

| Token | Replaced with |
|-------|---------------|
| `{name}` | Prospect's display name (or username) |
| `{hackathon_name}` | Value of `--hackathon-name` flag |
| `{listing_url}` | Value of `--listing-url` flag |

## Updating selectors (when DoraHacks changes their DOM)

1. Re-run recon: `npx rpa-outreach recon`
2. Review the updated `config/selectors.json`
3. Check the saved HTML/screenshots in `recon/` if selectors look wrong
4. Run a small scrape to verify: `npx rpa-outreach scrape`

The recon command overwrites `config/selectors.json` with freshly discovered selectors. No code changes required.

## Database

SQLite database (`outreach.db` by default) with a single `prospects` table. Created automatically on first run of any database command.

Prospect statuses flow through the pipeline:

```
scraped -> filtered -> queued -> messaged
                              -> failed
                              -> skipped
```

The `--db` flag on any subcommand lets you use a different database file.

## Troubleshooting

**"Browser context not found" or auth errors**
Delete the `auth/` directory and re-run any browser command. You'll be prompted to log in again.

**Selectors not matching / scraper returns 0 profiles**
DoraHacks likely changed their DOM. Re-run `npx rpa-outreach recon` to re-discover selectors. Check `recon/` for saved HTML snapshots to verify the page structure.

**"Rate limit exceeded" or send stops early**
The tool detected a rate limit or anti-bot measure. Wait before retrying. You can lower `rate_cap_per_hour` and increase delays in `config/defaults.json`.

**Captcha detected during send**
The sender stops automatically on captcha detection. Complete the captcha manually in the browser, then re-run `send` — it resumes from where it left off (already-messaged prospects are skipped).

**Duplicate profiles across runs**
The scraper deduplicates by username. Running `scrape` multiple times won't create duplicate entries.

**Database locked errors**
Ensure only one instance of the tool is running at a time. SQLite doesn't support concurrent writers.
